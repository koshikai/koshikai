## 常駐させると決めた理由

差分の確認、検証コマンドの実行、デプロイの監視。どれも毎回手順が決まった作業です。それでも席に着かないと進められず、離れているあいだは作業が止まっていました。会話が長くなると前のやり取りを引き継げなくなるうえ、モデルを乗り換えるたびに同じ前提を書き直すのも手間でした。

そこで自宅サーバーにエージェントを常駐させ、こうした作業を移しました。エージェント自身はリポジトリを持ちません。SSH 越しに各マシンへ入り、ファイルを編集してコマンドを流します。

## Hermes Agent の構成

使っているのは Nous Research が公開している [Hermes Agent](https://github.com/NousResearch/hermes-agent) です。単体で動き続ける自律エージェントで、CLI・デスクトップアプリ・メッセージングのゲートウェイのどれから入っても、同じセッションの続きを話せます。組み込みツールは 60 以上。MCP サーバー経由の外部ツールと、agentskills.io 互換のスキルも使えます。作業の手順をスキルとして書き戻す学習ループがあり、モデルとプロバイダは設定で差し替えられます。

実行場所は自宅の Proxmox VE 上の LXC 1 台。systemd でゲートウェイを常駐させ、状態・会話ログ・記憶・スキルはプロファイルごとのディレクトリに分けています。会話履歴と作業手順が混ざらないので、同じマシン上で用途ごとに別のプロファイルを同時に動かせます。MCP サーバーも接続済みです。Cloudflare の設定確認のような外部 API の操作を任せています。

## SSH 接続の構成

操作はすべて SSH 越しです。接続先は Proxmox のホスト、作業用の Windows 機、その WSL の 3 台。認証はメッシュ VPN 越しの鍵認証だけで、パスワード認証は使っていません。

`~/.ssh/config` の末尾に全ホスト共通の設定を置き、ControlMaster と ControlPersist 10m で接続を多重化しました。1 セッションで何十回もコマンドを実行するため、接続のたびにハンドシェイクを繰り返すと待ち時間がかさみます。確認待ちで処理が止まらないよう `BatchMode=yes` も指定済みです。

エージェントには「まず `git status` と `git log` を読み、ブランチ違いと未 push を確認してから触る」という手順をスキルとして渡しています。接続先が複数あると、コマンドを実行したホストと報告するホストを取り違える事故が起きるため、ホスト名の対応表もスキル側に持たせました。

## モデルの選定基準

主力は DeepSeek V4.1 Flash。2026-08 からの 154 セッションのうち 121 をこのモデルが処理しました。reasoning effort は low に固定しています。

理由は 3 つ。ツール呼び出しの形式が崩れにくいこと、1 セッションあたりのコストが低いこと、応答が速いことです。

トークンの 95% 以上はキャッシュ読み出しで賄われています。キャッシュ外の入力が 2,444 万、キャッシュ読み出しが 5 億 2,222 万トークン。長いシステムプロンプトとスキルを毎回送る構成なので、キャッシュから読み出せるかどうかで実質のコストが決まります。

重い設計の相談では上位モデルを 2 セッションだけ使い、実装は Claude Code と Codex CLI に委譲するスキルを用意しました。エージェントは委譲先の出力をレビューし、テストとビルドを通してから報告します。

## 長い会話の圧縮

1 段目は組み込みの圧縮です。コンテキストの 50%、このモデルでは 65,000 トークンに達した時点で自動的に走ります。直近 20 メッセージは原文のまま残し、それ以前を 20% 程度まで要約します。

2 段目は Lossless Context Management のプラグイン。圧縮で消えた部分を、要約の階層と原文の両方の形でローカルのデータベースに残します。全文検索と埋め込み検索のどちらからでも引けるので、要約だけでは足りないときに元のやり取りまで戻れます。このプロファイルのデータベースは 12.6MB、圧縮対象になったメッセージは 3,101 件です。

ツール出力が大きいときは、会話には参照 ID だけを残します。全文は必要になった時点で取得します。

要約の位置づけは「信頼しない履歴」です。指示として読み直さないようプロンプト側でも区切りました。圧縮したやり取りを現在の指示として解釈すると、過去の古い方針で現在の作業を上書きしてしまうためです。

## 状態の日次バックアップ

エージェントの状態は消えると復元できません。会話ログ、記憶、スキル、スケジュールを毎日 02:30 にまとめて退避しています。

- `hermes backup --quick` による全プロファイルのスナップショット取得
- スナップショットに含まれない会話データベースの、SQLite の backup API を使った一貫コピー
- プロファイルごとの tar.gz 化と、rclone の暗号化リモート経由での Google Drive への転送
- リモート 14 日・ローカル 2 日保持、cron の二重起動防止（flock）

## 委譲の範囲と手順

委譲しているのは、差分と履歴の確認、検証コマンドの実行、デプロイの監視、ログの調査まで。採用するか、push するか、公開するかは自分で決めています。

作業中につまずいた点はその場でスキルに書き戻し、次のセッションで同じ失敗を繰り返さないようにしました。モデルを乗り換えてもスキルと会話ログは残るので、手順を書き直さずに移行できます。
