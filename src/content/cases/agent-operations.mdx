## 常駐させると決めた理由

作業のたびに手順を思い出し、同じ確認を手で繰り返していました。差分の確認、検証コマンドの実行、デプロイの監視は毎回同じ形なのに、その都度人間が席に着く必要がありました。会話が長くなると文脈が切れ、モデルを乗り換えるたびに同じ前提を書き直す作業も残っていました。

そこで自宅サーバーにエージェントを常駐させ、定型作業を移しました。エージェント自身はリポジトリを持たず、SSH 越しに各マシン上で編集・実行する形です。

## Hermes Agent の構成

使っているのは Nous Research が公開している [Hermes Agent](https://github.com/NousResearch/hermes-agent) です。IDE に紐づく補完ではなく、単体で動き続ける自律エージェントで、CLI・デスクトップアプリ・メッセージングのゲートウェイから同じセッションに触れます。60 以上の組み込みツール、MCP サーバー経由の外部ツール、agentskills.io 互換のスキルを持ち、作業の手順をスキルとして書き戻す学習ループがあります。モデルとプロバイダは設定で差し替えられます。

実行場所は自宅の Proxmox VE 上の LXC 1 台です。systemd でゲートウェイを常駐させ、状態・会話ログ・記憶・スキルはプロファイルごとのディレクトリに分かれています。会話履歴と作業手順が混ざらないので、同じマシン上で別の文脈を持つ相手として並走させられます。MCP サーバーも接続していて、Cloudflare の設定確認のような外部 API の操作を任せています。

## SSH 接続の構成

エージェントはすべての操作を SSH 越しに行います。接続先は Proxmox のホスト、作業用の Windows 機、その WSL の 3 台です。認証はメッシュ VPN 越しの鍵認証だけで、パスワード認証は使っていません。

`~/.ssh/config` で全ホストに共通の設定を末尾に置き、ControlMaster と ControlPersist 10m で接続を多重化しています。1 セッションで何十回もコマンドを打つので、ハンドシェイクの往復を毎回払うと体感がはっきり変わります。`BatchMode=yes` を付けて、確認待ちで止まらないようにもしています。

エージェントには「まず `git status` と `git log` を読み、ブランチ違いと未 push を確認してから触る」という手順をスキルとして渡してあります。接続先が複数あると、叩いた先と報告する先がずれる事故が起きます。ホスト名の対応表もスキル側に持たせました。

## モデルの選定基準

主力は DeepSeek V4.1 Flash です。2026-08 からの 154 セッションのうち 121 をこのモデルが処理し、reasoning effort は low に固定しています。残りは移行前のモデルでの記録です。選んだ理由は、ツール呼び出しの形式が崩れにくいこと、1 セッションあたりのコストが低いこと、応答が速いことです。

入力全体の 95% 以上がキャッシュ読み出しで賄われています（キャッシュ外の入力 2,444 万トークンに対し、キャッシュ読み出し 5 億 2,222 万トークン）。長いシステムプロンプトとスキルを毎回送る構成なので、キャッシュが効くかどうかが実質のコストを決めます。モデルを比べるときは単価よりこの比率を見ています。

重い設計の相談では上位モデルを 2 セッションだけ使い、実装は Claude Code と Codex CLI に委譲するスキルを用意しました。エージェントは委譲先の出力をレビューし、テストとビルドを通してから報告します。

## 長い会話の圧縮

1 段目は組み込みの圧縮です。コンテキストの 50%、このモデルでは 65,000 トークンに達した時点で自動的に走り、直近 20 メッセージは原文のまま残し、それ以前を 20% 程度まで要約します。

2 段目が Lossless Context Management のプラグインです。圧縮で消えた部分は、要約の階層と原文の両方をローカルのデータベースに残し、全文検索と埋め込み検索の両方から引けるようにしています。要約だけでは足りないときに元のやり取りまで降りられます。このプロファイルのデータベースは 12.6MB、圧縮対象になったメッセージは 3,101 件です。ツール出力が大きい場合は会話には参照 ID だけを残し、必要になった時点で全体を取り戻す形にしています。

要約は「信頼しない履歴」として扱い、指示として読み直さないようにプロンプト側でも区切っています。畳んだ結果が指示に化けると、過去の古い方針が現在の作業を上書きします。

## 状態の日次バックアップ

エージェントの状態は、消えると復元できない種類のデータです。会話ログ、記憶、スキル、スケジュールを毎日 02:30 にまとめて退避しています。

- `hermes backup --quick` による全プロファイルのスナップショット取得
- スナップショットに含まれない会話データベースの、SQLite の backup API を使った一貫コピー
- プロファイルごとの tar.gz 化と、rclone の暗号化リモート経由での Google Drive への転送
- リモート 14 日・ローカル 2 日保持、cron の二重起動防止（flock）

## 委譲の範囲と手順

委譲しているのは、差分と履歴の確認、検証コマンドの実行、デプロイの監視、ログの読み解きまでです。採用するかどうか、push するかどうか、公開するかどうかは自分で決めています。

作業で覚えた落とし穴はその場でスキルに書き戻します。同じ失敗を次のセッションで繰り返さないための仕組みです。モデルを乗り換えてもスキルと会話ログは残るので、手順を書き直さずに移行できます。
