## 背景

数万枚規模の写真・動画を、プライバシーを保ちつつ快適に管理するため、Google フォトの代替として Immich を導入しました。しかし、顔認識や機械学習による分類には強力な GPU が必要であり、低消費電力な Proxmox ノード単体では処理能力が不足していました。

## 課題

- Proxmox ノードの CPU だけでは、数千枚の画像に対する顔認識・クリップ分類が数日経っても終わらない。
- メインマシンの Windows には強力な GPU があるが、サービス自体は 24 時間稼働のサーバー側で運用したい。
- ネットワークを跨いで GPU リソースを効率的に共有する構成が必要。

## 判断

Immich のマイクロサービス構成を活かし、**「DB/Web は Proxmox、機械学習タスクのみ Windows GPU」**という分散アーキテクチャを採用しました。

## 実装

- **コンテナ分離:** Docker Compose を使用し、`immich-server` 等の基本機能を Proxmox 上に、`immich-machine-learning` のみを Windows 側の Docker 環境へ分離。
- **GPU パススルー:** Windows 側 Docker で NVIDIA Container Toolkit を使用し、RTX シリーズの GPU をコンテナに開放。
- **リモート連携:** `immich-server` からネットワーク越しに Windows 側の ML エンドポイントを叩くよう設定。
- **高速化:** この構成により、これまで数日かかっていた初期スキャンが数時間に短縮され、快適な写真検索が実現。

## 結果

自宅内の余剰リソース（ゲーミング PC の GPU 等）を、サーバーサイドのサービスに動的にオフロードする仕組みを構築できました。これにより、低コストな常時稼働サーバーと、高性能な処理能力を両立しました。

## 学び

コンテナベースのマイクロサービスであれば、物理的なマシンの境界を越えてリソースを最適配置できるという、実践的な分散システムの設計手法を学びました。

## 次の改善

- Windows マシンの起動状態に合わせた、動的なリソーススケジューリングの検討。
- 10GbE 導入による、画像転送のさらなる高速化。
