## 省電力サーバーの限界と、眠っている GPU

自宅で Proxmox サーバーを動かし、写真管理や DNS、リバースプロキシなどを運用しています。常時稼働させるサーバーは電気代を抑えるため省電力な小型ノードを選びましたが、Google フォトの代替として写真管理ツール「Immich」を導入したことで壁に当たりました。

数万枚の写真を取り込んで顔認識や CLIP による画像分類を走らせると、CPU 使用率が張り付き、数日経ってもスキャンが終わりません。一方で、普段使いの Windows PC には強力な NVIDIA GPU が積まれているものの、日中はゲームや作業をしていない限り遊んでいます。「24時間動く省電力サーバー」と「たまに動く高性能 GPU」をどう繋ぎ合わせるかが課題になりました。

## 常時稼働と機械学習処理を切り離す

Immich のマイクロサービス構成に着目し、WebUI やデータベース（PostgreSQL）といった基本機能は 24時間動く Proxmox 側に置き、重い機械学習処理（`immich-machine-learning`）だけを LAN 越しの Windows PC へオフロードする分散構成を取りました。

- **処理の分離:** Proxmox 側の `docker-compose.yml` から機械学習コンテナを外し、リモートエンドポイントとして Windows PC の IP とポートを指定
- **GPU の開放:** Windows 側の WSL2 / Docker 環境に NVIDIA Container Toolkit を導入し、RTX シリーズの GPU をコンテナへパススルー
- **ネットワーク経由の推論:** 写真の取り込みや再スキャン時、Proxmox から Windows 側のエンドポイントへ推論リクエストを投げる構成に整理

## 数日かかっていたスキャンが数時間に縮んだ

この構成に切り替えたところ、CPU だけでは何日もかかっていた数万枚の初期スキャンが数時間で完了しました。

常時稼働させるサーバーの消費電力を低く抑えつつ、重いバッチ処理のときだけ手元のゲーミング PC の資源を借りる。単一のハードウェアにすべてを詰め込むのではなく、ネットワーク越しに役割を分担させることで、電気代と処理性能の両方を妥協せずに済みました。

## 10 以上のコンテナを抱えて気づいた運用の芯

写真管理以外にも、リバースプロキシ（Nginx Proxy Manager）や広告ブロック（AdGuard Home）など、運用するコンテナが 10 を超えると「どの設定をどう弄ったか」が散らかり始めます。

そこで、設定のバックアップやコンテナの起動手順をスクリプト化し、手順を固定化しました。自動化の恩恵は処理が速くなること以上に、「いつ触っても同じ状態に戻せる」という再現性の担保にあります。
