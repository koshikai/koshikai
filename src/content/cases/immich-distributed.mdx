## 省電力サーバーの限界と、眠っている GPU

自宅の Proxmox サーバーで、Google フォトの代替として写真管理ツール「Immich」を動かしています。常時稼働させるサーバーは電気代を抑えるため省電力な小型ノードを選びましたが、Immich の導入で壁に当たりました。

数万枚の写真を取り込んで顔認識や CLIP による画像分類を走らせると、CPU 使用率が張り付き、数日経ってもスキャンが終わりません。一方で、普段使いの Windows PC には強力な NVIDIA GPU が積まれているものの、日中はゲームや作業をしていない限り遊んでいます。「24時間動く省電力サーバー」と「たまに動く高性能 GPU」をどう繋ぎ合わせるかが課題になりました。

## 推論だけを切り離す

Immich は WebUI やデータベースと、機械学習の推論（`immich-machine-learning`）が別プロセスに分かれています。前者は 24 時間動く LXC に置いたまま、推論の送り先だけを LAN 越しの Windows PC に向けました。

送り先は環境変数 `IMMICH_MACHINE_LEARNING_URL` で Windows PC のポート 3003 に指定します。LXC 側のローカル ML は待機用に残してあり、常用は GPU 側です。

Windows 側では WSL コンテナ（wslc）で CUDA 版の機械学習イメージを動かし、RTX の GPU をそのまま推論に使います。WSL のネットワークはミラーモードにして、LAN 上のサーバーから端末へ直接届くようにしました。wslc のコンテナは自動再起動の仕組みを持たないため、ログオン時に起動するスクリプトをスタートアップに置き、コンテナが無ければ pull して作り直します。

使うモデルは次の 3 つです。画像検索の CLIP は多言語の `XLM-Roberta-Large-ViT-H-14` にしました。Immich 公式のベンチマークで日本語クエリの再現率が 83.95% と候補の中で最も高く、SigLIP2 系は英語では上回っても日本語では 65% 前後に落ちます。顔は `antelopev2`、文字認識は `PP-OCRv5` で、どちらも公式が示す最大クラスのモデルです。

## 数日かかっていたスキャンが数時間に縮んだ

この構成に切り替えたところ、CPU だけでは何日もかかっていた初期スキャンが数時間で完了しました。GPU 側の実測では、1 枚の画像の顔検出と CLIP の埋め込みが約 60 ミリ秒、検索語 1 つの埋め込みが約 15 ミリ秒です。連続で投げると GPU の使用率は 70〜100% まで上がり、待機中は 10% 前後に戻ります。

常時稼働のサーバーは消費電力を低く保ち、重いバッチ処理のときだけ手元のゲーミング PC の GPU を借ります。役割をネットワーク越しに分けたので、電気代と処理性能の両方を確保できました。

## 本体と推論コンテナのバージョン固定

Immich 本体と ML コンテナは同じバージョンで動かします。食い違うと動作が不安定になると公式も注意していて、v3 系ではリクエストの形式自体がマイナーバージョンで変わるためです。ML 側は起動スクリプトのイメージタグ（`v3.4.1-cuda` など）で固定しているので、更新は次の順に進めます。

1. 本体の LXC で `pg_dump` を取る
2. 新しいイメージを Windows 側へ先に pull する（旧コンテナは動かしたまま）
3. 本体を更新する。ビルドに 6 GB のメモリが要るので LXC の割り当てを一時的に上げ、15〜25 分かかる
4. コンテナを新しいタグで作り直し、起動スクリプトのタグを書き換える
5. `/ping` の応答、`CUDAExecutionProvider` の有効化、本体ログの `became healthy`、実写を使った推論の順に確かめる

## GPU 側に届かなかったとき

ある夜、写真を取り込んだ直後に顔検出・画像検索・文字認識の 3 ジョブが `fetch failed` で失敗しました。送り先を GPU 側の 1 つに絞っているので、ローカル ML には自動で切り替わらず、ジョブは失敗として残ります。

写真の取り込みと閲覧は止まらないため、GPU 側の復旧後に管理画面の Jobs から「Missing」を選び、未処理の分だけ再実行します。

## 運用で踏んだ細かい点

リバースプロキシで WebSocket を許可していないと、Web 画面の `socket.io` 接続が 400 で失敗し、ジョブの進捗は 2 秒ごとの再取得に落ちます。許可すると 101 で接続できました。

`web.log` は 5.5 GB まで膨らんでいたので logrotate を入れ、100 MB を超えたら世代交代して 7 世代まで残します。

wslc は pull したイメージとボリュームがセッションごとに別物です。SSH のセッションで pull したイメージはコンソール側から見えず、別のセッションでコンテナを作るとモデルの cache も空から始まります。
