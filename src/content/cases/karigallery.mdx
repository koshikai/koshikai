## 背景

友人のイラストを展示・管理するギャラリーサイトとして制作しました。

## 課題

- 友人のイラスト資産を一箇所で管理・公開したい
- 将来的に販売も視野に入れ、決済機能の技術検証も行いたい
- 大容量になりがちな画像のアップロード負荷を軽減したい
- 直感的で滑らかな画像閲覧体験の構築

## 判断

Next.js (v16.2), Prisma (v7.7), Auth.js, Stripe を採用し、クライアント側の画像処理を組み込むことにしました。

## 実装

- **フルスタック基盤:** Auth.js による認証と Stripe API による決済機能の統合
- **画像最適化:** `browser-image-compression` によるアップロード時の軽量化
- **リッチな操作:** `react-zoom-pan-pinch` によるズーム・パン、Framer Motion による洗練されたアニメーション
- **型安全な DB 運用:** Prisma v7.7 と PostgreSQL による堅牢なデータ設計

## 結果

技術的には Stripe Checkout による決済フローを実装・検証完了していますが、本番で金銭を扱うには特定商取引法に基づく表記や税務処理など、個人開発者の負荷が大きい法的手続きが必要です。現時点ではこれらを「やらない判断」をし、決済機能を無効化した上で、**偽名を使ったダミーデータを表示するギャラリーとして運用しています**。必要な手続きが整えばいつでも販売を開始できる状態です。

## 学び

技術的に可能なことでも、それを実際に運用に載せるかどうかは、法律面のコストや運用負荷も含めて総合的に判断する必要があると学びました。また、Auth.js や Stripe といった外部サービスとの API 連携において、堅牢なデータモデルを設計する重要性も実感しました。
