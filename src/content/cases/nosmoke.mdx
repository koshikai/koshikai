## 背景

禁煙・減煙を何度も挑戦する中で、既存アプリの「登録が面倒」「見た目が医療的すぎて続かない」「自分のデータが手元に残らない」といった不満を感じていました。スマホのホーム画面に置いて、気軽に1本記録でき、記録を見返したときに達成感が得られるツールが欲しいと考え、自分自身が使うことを前提に開発を始めました。

目標は「ネイティブアプリと区別がつかないPWA体験」を作ること。Webながらオフラインで動作し、インストール不要の手軽さと、通知やアニメーションによる没入感を両立させたいと考えました。

## 課題

- **オフライン環境での継続性:** 通信状況が不安定な場面（外出先や地下鉄内）でも記録を途切れさせたくない
- **モチベーション維持:** 単調な記録作業だと3日坊主になりがち。視覚的なフィードバックとゲーミフィケーションが必要
- **モバイル最適化:** スマホでのワンタップ記録と、親指で操作しやすいUIが必須。Safe AreaやTouch Targetの配慮も必要
- **データの継続的な活用:** 過去の記録を振り返り、パターンや改善点を自分で分析できる仕組みが欲しい
- **継続支援の仕組み:** 記録だけでなく、ピンチの時に相談できる存在が欲しい

## 判断

**Next.js (v16.2), React 19, Tailwind CSS v4, Bun** を採用。最新技術の恩恵を最大限に受けつつ、PWAとしての実装を徹底しました。

認証は **Auth.js (NextAuth v5)**、ORM は **Prisma v7.8**、データベースは **PostgreSQL** を選択。ユーザー認証からデータ永続化まで、型安全なフルスタック基盤を構築しました。

UI/UX には **Framer Motion** を活用し、ネイティブアプリのような有機的なアニメーションを再現。グラフ描画には **Recharts**、アイコンには **Lucide React** を採用しました。

PWA 化には **Serwist** を使用し、Service Worker によるオフライン対応と **Web Push API** によるプッシュ通知を実装。通知基盤には **web-push** ライブラリと VAPID キーを使用しています。

AI コーチ機能には **OpenRouter API** を採用。ユーザーの喫煙データに基づいたパーソナライズドアドバイスを、ストリーミングで返答する仕組みを構築しました。

## 実装

### PWA 基盤とオフライン対応

**Serwist** による Service Worker の自動生成に加え、開発環境での Service Worker クリーンアップ機構を自前で実装。ローカル開発時のキャッシュ競合を防ぎ、スムーズな開発体験を維持しました。

`manifest.json` では `display: standalone` と `orientation: portrait` を指定し、スマホネイティブアプリのような起動体験を実現。アイコンは `purpose: any maskable` に対応させ、Android のアダプティブアイコンにも対応しています。

オフライン状態は `navigator.onLine` と `online`/`offline` イベントで検知し、画面上部に非侵襲的なバナーを表示。レイアウトには `env(safe-area-inset-*)` を考慮し、ノッチやホームインジケーターとの干渉を防いでいます。

### ネイティブ級の UI/UX 設計

**Glassmorphism 2.0** を基調としたデザインシステムを構築。CSS 変数による動的テーマ（ライト/ダーク）を実装し、ダークモード時は `#000000`（True Black）を基調とした OLED 対応設計を採用。バッテリー消費とコントラストの最適化を両立させました。

レイヤー構造は Z-index を明確に分離し、Base（背景グラデーション）→ Content（カード）→ Floating（ナビゲーション）→ Overlay（ダイアログ）の4層で管理。 backdrop-filter によるガラス質感は、モバイルでは GPU 負荷を考慮して無効化する最適化も行っています。

タイポグラフィは Fluid Scale（`clamp()` ベース）を採用し、ビューポート幅に応じた動的スケーリングを実現。タッチターゲットは全要素で `44px × 44px` 以上を確保し、WCAG 2.2 Level AA（コントラスト 4.5:1）を遵守しています。

ボトムナビゲーションは親指ゾーンを意識した配置で、モバイルでは画面下部に固定されたフローティングタブバーを表示。デスクトップではヘッダーナビゲーションに切り替わるレスポンシブ設計です。隣接タブのプリフェッチも実装し、画面遷移の高速化を図りました。

### ワンタップ記録と Optimistic UI

ダッシュボード画面では「1本記録する」ボタンを中央下部に配置し、親指で届く位置からワンタップで記録できます。記録時は **Optimistic UI** を採用し、API レスポンスを待たずに即座にカウンターを更新。Framer Motion の `useSpring` と `animate` で、数字が滑らかにカウントアップするアニメーションを演出しています。

記録失敗時は自動でロールバック。ボタンには `pulse-ring` アニメーションによる視覚的フィードバックを加え、操作が確実に受け付けられたことを伝えます。また、`aria-live` 属性を付与し、スクリーンリーダーでも現在の本数が読み上げられるようにしています。

目標本数に対する残り本数をトースト通知で表示。目標達成時には特別なメッセージを出し、継続意欲を高めます。

### タイムラインと可視化

**DailyTimeline** コンポーネントでは、24時間を1本のタイムラインで表現。記録した時刻に縦棒グラフ（ネオンバー）を立て、現在時刻のラインと重ねて表示します。Framer Motion のスプリングアニメーションで、棒が下から伸びる演出を加えています。

**LogsChart** では Recharts の BarChart を使用。タバコをモチーフにしたグラデーション（フィルター部分＝オレンジ、紙部分＝白、火口部分＝赤灰）を独自にデザインし、視覚的な親しみやすさを演出。期間切り替え（7日/4週間/全期間）に応じて、日別・週別・月別の集計を動的に切り替えます。

### ゲーミフィケーション（バッジシステム）

9種類のバッジを実装し、達成条件を満たすと自動付与されます。バッジには「最初の一歩」「三日坊主卒業」「一週間達成」「一ヶ月達成」といった禁煙・減煙の節目に加え、「節約家デビュー（1,000円）」「ちょっと贅沢（5,000円）」「有言実行（銅/銀/金）」といったモチベーション維持要素も含まれています。

バッジ詳細モーダルでは **Three.js** と **@react-three/fiber** を使用し、3D の回転メダルを表示。絵文字テクスチャを Canvas で動的に生成し、金の縁とリボンが付いたメダルが浮遊する演出を実現しています。未獲得バッジはグレースケールで表示され、獲得意欲を刺激します。

### AI コーチ機能

OpenRouter API（`openrouter/free` モデル）をバックエンドに、ユーザーの喫煙データに基づいた **パーソナライズドAIコーチ** を実装。システムプロンプトには以下の情報を動的に注入します：

- 記録開始日
- 実績サマリー（本日の本数、総記録日数、総本数、直近7日間の平均本数）
- 直近4週間の日別記録（JSON形式）

フロントエンドでは Server-Sent Events（SSE）によるストリーミングレスポンスを実装。AIの回答がリアルタイムに表示され、タイピングしているような臨場感を演出しています。会話履歴はセッション単位で管理し、新しい会話を開始できるようにしています。

コーチの初期メッセージは、ユーザーの直近7日間の平均と目標を比較し、達成できていれば称賛、未達成であれば励ましの言葉を自動生成します。

### プッシュ通知基盤

**Web Push API** と **VAPID** キーを使用したプッシュ通知基盤を構築。ユーザーが許可すると、ブラウザの PushSubscription 情報を PostgreSQL に保存します。

Cron ジョブ（`/api/cron`）では、朝夕の時間帯に応じて異なるメッセージを配信：
- **朝（7〜9時）:** 「おはようございます。新しい1日の始まりです。」
- **夜（19〜21時）:** 「お疲れ様でした。今日も1日よく頑張りましたね。」

無効な購読（410 Gone）は自動でクリーンアップし、配信成功率を維持しています。

### データ設計と型安全性

Prisma スキーマで以下のモデルを設計：
- **User / Account / Session:** Auth.js による認証管理
- **UserSettings:** 喫煙習慣、目標本数、タバコ価格、オンボーディング状態
- **Log:** 喫煙記録（本数、メモ、タイムスタンプ）
- **UserBadge:** 獲得バッジの管理
- **CoachMessage:** AIコーチとの会話履歴
- **PushSubscription:** プッシュ通知購読情報

`userId` と `created_at` の複合インデックスを貼ることで、記録の時系列クエリを最適化。Server Actions によるデータ取得・更新は、認証チェック後に `revalidatePath` で関連ページを再検証し、キャッシュと整合性を保ちます。

### オンボーディング体験

初回利用時には3ステップのオンボーディングウィザードを表示：
1. **ようこそ:** アプリの概要説明
2. **現状の確認:** 1日の平均本数と1箱の値段を入力
3. **目標設定:** 無理のない範囲で目標本数を設定

ステップの進捗はローカルストレージに保存され、中断しても再開できます。入力値は即座に計算結果に反映され、現在の設定値より少し減らすことを推奨するヘルパーテキストを表示します。

### テスト体制

**Jest** と **React Testing Library** による網羅的なテストを実装。主要なユーティリティ関数（統計計算、バッジ判定、設定変換、セキュリティチェック等）に対して単体テストを作成し、カバレッジレポートを生成しています。

環境変数の検証、リクエストセキュリティ（Cron認証、HTTPSリダイレクト）、API ユーティリティなど、インフラ層のテストも含め、堅牢性を高めています。

### アクセシビリティとパフォーマンス

- **スクリーンリーダー対応:** 動的な数値変更に `aria-live="polite"` を設定
- **キーボードナビゲーション:** 全インタラクティブ要素に `focus-visible` リングを設定
- **リデュースモーション:** `prefers-reduced-motion` メディアクエリでアニメーションを無効化
- **スケルトンスクリーン:** コンテンツ読み込み中のレイアウトシフトを防止
- **OLED ダークモード:** True Black でバッテリー消費を抑制

## 結果

オフライン環境でも動作する信頼性と、スムーズなアニメーションによる高いユーザー体験を両立させました。ワンタップ記録の導線により、記録の手間を最小化。タイムラインとチャートによる可視化で、自分の喫煙パターンを客観的に把握できるようになりました。

AIコーチの導入により、記録するだけでなく「相談できる相手」がいるという安心感が生まれました。バッジシステムと節約額の可視化により、達成感が数値として実感でき、継続モチベーションの維持に寄与しています。

## 学び

- **Optimistic UI の重要性:** Web とネイティブの境界を曖昧にするには、操作に対する即座のフィードバックが不可欠。ロールバック機構を伴う楽観的更新は、ユーザー体験とデータ整合性の両立に有効でした
- **PWA の Service Worker 管理の複雑さ:** キャッシュ戦略と更新タイミングを最初に設計すべきだった。開発時のクリーンアップ機構が後から必要になり、事前設計の重要性を学びました
- **Glassmorphism の性能トレードオフ:** backdrop-filter は美しいが、モバイルでは GPU 負荷が高い。メディアクエリで最適化し、デスクトップとモバイルで異なる質感を提供する判断が有効でした
- **AI 連携におけるコンテキスト設計:** システムプロンプトに「どのデータを」「どの粒度で」注入するかが、回答の質を大きく左右。ユーザーの全履歴ではなく直近4週間の集計に絞ることで、トークン数と回答精度のバランスを取りました
- **継続行動を支える UI 設計:** 禁煙という継続行動を支えるには「達成感の可視化」と「最小抵抗の記録導線」が最重要。1本記録ボタンの配置や、節約額の即座な表示が、モチベーション維持に直結しました
