## 「続かない・医療的すぎる」不満から生まれた PWA

喫煙本数や支出を記録して自分の習慣を振り返ろうとしたとき、既存の禁煙・節煙アプリにいくつかの不満を感じていました。ログインや初期登録の手数が多く、画面デザインも医療的・警告的すぎて開くのが億劫になる。さらに記録したデータのエクスポートが難しく、自分のデータなのに手元に残らない点にも違和感がありました。

そこで、スマホのホーム画面からワンタップで1本を記録でき、銘柄や支出の推移を気軽に振り返れる個人用 PWA を開発しました。目指したのは「ネイティブアプリと見分けがつかない滑らかさと、Web ならではの気軽さの両立」です。

## 習慣記録アプリが抱える壁

- 地下鉄や飲食店などの電波が届きにくい場所でも、記録の手間や待ち時間なく使えること
- 単なる入力作業に終わらず、タイムラインやグラフで自分の行動傾向を把握できること
- スマホ片手・親指一本で確実に記録できる UI と、誤タップ時の手戻りの少なさ
- 記録をためるだけでなく、吸いたくなったときに状況を整理できる対話機能

## 技術選定: Next.js 16 と Serwist による PWA 化

フロントエンドとバックエンドの境界を減らすため、Next.js (App Router) と React 19、Tailwind CSS v4 を採用しました。ランタイムには Bun を選んでいます。

認証には Auth.js、データ永続化には PostgreSQL と Prisma を組み合わせ、ユーザーごとの記録と設定を型安全に管理しています。

PWA 化の核には Serwist を採用しました。Service Worker によるアセットの事前キャッシュとオフラインフォールバックを組み、Web Push API と VAPID キーによる通知基盤も実装しました。アニメーションには Framer Motion、グラフ描画には Recharts を用いています。

AI コーチ機能は OpenRouter API を介し、ユーザーの直近の記録傾向を踏まえたアドバイスをストリーミング（SSE）で返す構成にしました。

## 操作性と習慣化を支える設計

### オフライン対応と PWA 構成

`manifest.json` で `display: standalone` を指定し、スマホの全画面で起動するように整えました。

Serwist による Service Worker 生成に加え、ローカル開発時にキャッシュが残って動作確認を阻害しないよう、開発環境限定の Service Worker クリーンアップ機構を自前で用意しました。通信が途切れた際は画面上部に控えめなインジケーターを出し、オフライン時でも操作を受け付けられるようにしています。

### 親指で完結するワンタップ記録と Optimistic UI

画面中央下に「1本記録する」ボタンを大きく配置し、親指の届く範囲からワンタップで記録できるようにしました。

記録時はサーバーからの応答を待たずに画面の数値を即座に増やす Optimistic UI（楽観的更新）を採用しています。Framer Motion のスプリングアニメーションでカウンターが滑らかに跳ね上がり、触れた感触を視覚で返します。通信エラーが発生した場合は自動で元の本数へロールバックし、不整合を防ぐ設計にしました。

### タイムラインとグラフによる傾向の可視化

24時間を横断するタイムラインコンポーネントを用意し、何時何分に吸ったかを縦棒グラフで可視化しました。

あわせて、7日間・4週間・全期間で切り替え可能な集計チャートを実装し、時間帯や曜日ごとの偏り、日々の支出額の推移を一目で把握できるようにしています。昨日と比べた増減が数値として確認できるため、客観的に自分の習慣と向き合えます。

### 過去データを踏まえて助言する AI コーチ

ただ一般的な禁煙アドバイスを返すのではなく、ユーザー自身の直近データを踏まえて対話できる AI コーチを組み込みました。

システムプロンプトには、記録開始からの日数、直近7日間の平均本数、直近4週間の日別集計データを動的に渡します。「最近は夕方以降の本数が増えていますね」「週末の出費が抑えられています」といった、本人の生活リズムに即した返答がストリーミングで返るようにしました。

### データ設計とインデックス最適化

Prisma スキーマでは、ユーザー設定、銘柄マスタ、喫煙ログ、獲得バッジ、プッシュ通知購読情報などを定義しています。

記録ログは時系列での参照頻度が高いため、`userId` と `created_at` の複合インデックスを設定し、期間指定の集計クエリが遅延しないよう配慮しました。

## 手間を削り、振り返りと相談の場を作った

記録の手間をワンタップまで削ったことで、外出先でも途切れずに記録を継続できるようになりました。タイムラインによって「自分がどの時間帯に吸いたくなるのか」という無自覚な癖が浮き彫りになり、行動を見直すきっかけが生まれます。

また、AI コーチがいることで、単なる数字の管理ツールから「生活習慣を相談できる相手」へと体験が変わりました。

## 開発を通じて得た知見と反省

- **Optimistic UI は必須の投資だった:** ボタンを押してからサーバーの往復を待たせるUIでは、日常の記録は続きません。即座に画面が反応し、裏で通信する体験こそがアプリの軽快さを作ると実感しました。
- **Service Worker のキャッシュ設計は最初に固めるべきだった:** 開発中のキャッシュ残りはデバッグの大きなノイズになります。最初から開発用と本番用のライフサイクルを切り分けて設計しておくべきでした。
- **AI へのコンテキスト注入は絞り込みが命:** 当初は全期間のログを渡そうとしましたが、トークン消費が増えるだけでなく、かえって直近の変化に対するアドバイスの解像度が落ちました。直近4週間の集計に絞って渡す設計が最も安定した回答を生みました。
